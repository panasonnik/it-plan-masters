# Міграції бази даних

Каталог `backend/db/migrations`, накочує `npm run migrate` (`backend/src/migrate.js`):
нові файли за порядком назв, кожен у своїй транзакції; застосовані записуються в
таблицю `migrations`. Нові зміни схеми додаються наступними файлами (`003_…`).

| Файл | Що робить |
|---|---|
| `001_schema.sql` | 14 таблиць: користувачі, типи обладнання, обладнання, споживачі, симптоми, нормативи, регламенти обслуговування, робочий час, налаштування, заявки, історія заявок, роботи, план на сьогодні, сповіщення; первинні й зовнішні ключі, обмеження, індекси |
| `002_seed.sql` | демо-дані: 8 користувачів (2 адміністратори, 6 працівників), 11 типів і 26 одиниць обладнання, 12 записів про споживачів, 28 симптомів, 32 нормативи, 22 регламенти, робочий тиждень пн–пт 09:00–18:00 з обідом 13:00–14:00, 4 налаштування |
| `003_work_types_and_fk.sql` | довідник `work_types` (код і назва), заповнений видами робіт, які вже є в даних; зовнішні ключі `work_type` з `symptoms`, `service_norms`, `maintenance_rules`, `tasks` на нього (`ON UPDATE CASCADE`); зовнішній ключ `notifications.task_id` на `tasks` (`ON DELETE SET NULL`), перед ним посилання на неіснуючі роботи обнуляються |
